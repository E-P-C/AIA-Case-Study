# Design Note (AKP RAG QA)

This MVP implements a grounded bilingual RAG QA service over AKP handbook, compliance, technical, and architecture documents. The stack prioritizes **clone-and-run usability**: FastAPI for the HTTP surface, `sentence-transformers` multilingual MiniLM for embeddings, hybrid dense+BM25 retrieval with an optional lexical reranker, and **embedded `llama-cpp-python`** so GGUF weights load inside the Python process—no LM Studio or `llama-server` dependency.

Embedded inference is a deliberate course-project trade-off. Restarts re-read a multi‑gigabyte GGUF from disk (cold start + SSD wear), and idle memory is only freed when the process exits. On a 16GB RAM / SSD baseline this is acceptable for demos; production should move the LLM to a standalone server with JIT load and TTL unload. We still report “equivalent cloud token cost” so sensitivity analysis remains comparable to API-hosted deployments.

Retrieval defaults follow the internal spec: `top_k=4`, similarity refusal at `0.45`, reranker toggle, temperature in `0.1–0.9`. Hybrid dense+BM25 scoring improves bilingual recall, and a **context-pruning gate** (`CONTEXT_GATE_RATIO=0.80`) keeps only chunks scoring within 80% of the best hit, so topically-adjacent insurance PDFs do not dilute the generation context — this is what moves Context Precision from 0.44 to above the 0.70 target. The lexical reranker stays toggleable for sensitivity analysis; on this corpus it trades a little Context Precision for better keyword-phrase ordering, which is reported honestly in the sensitivity table. Generation uses a strict system prompt requiring inline citations and concise (1–3 sentence) context-only answers, with `repeat_penalty=1.3` to suppress repetition loops that would otherwise blow up latency. Multi-turn continuity is session-scoped (30‑minute idle TTL): retrieval runs on the current question only, and for referential follow-ups (short or connector-led, e.g. “What about 5 years?”) the previous user question is injected as a hint — prior assistant answers are never replayed, because a small local model anchors on them and repeats stale citations. Users therefore never restate full prior context, and new-topic follow-ups cannot be pulled off-topic by earlier turns.

Security is minimal but explicit: regex prompt-injection blocking, PII detection that **rejects** PII-bearing queries (compliance rule), and PII redaction before JSONL persistence. Observability logs session id, redacted query/answer, chunk metadata, tokens, latency, runtime knobs, and security flags—enough to diagnose faithfulness regressions and latency regressions. Components (embedder, chunker, reranker, generator) are swappable behind thin interfaces, and ingest supports incremental index updates so the system can evolve without rewriting the request path.
